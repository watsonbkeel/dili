# dili 腾讯云部署说明

适用分支：`cloud/tencent-migration`。目标：把后端、图片、运行数据迁到新腾讯云服务器，保留域名 `dili.bkeel.com`，语音识别改用腾讯云一句话识别。

> **2026-09-30 实际落地情况（优先看这里）**
> - 部署在香港服务器 43.161.244.217（Tailscale 100.117.92.13，Debian 13）。它原本就是 `dili.bkeel.com` 的 Nginx 入口，以前转发到内网机器 `100.74.3.56:13104`（已故障）。
> - 所以**没有改 DNS**，只把 `/etc/nginx/sites-available/dili-bkeel-https` 的上游改为 `127.0.0.1:13104`（线上内容见 `deploy/tencent/nginx-dili-bkeel-https.live.conf`），`nginx -t` 通过后执行 `reload`。其他站点不受影响。
> - Node 用 Debian 源里的 `nodejs` 20.19.2（没装 npm）。发布包在本机 `npm ci --omit=dev` 后连同 `node_modules` 一起打包；`deploy.sh` 检测到包里已有依赖就会跳过 `npm ci`。
> - 在 macOS 上打包必须加 `COPYFILE_DISABLE=1 tar --no-xattrs --no-mac-metadata`，不然 Debian 的 tar 会报 xattr 警告。
> - 证书沿用 `/etc/letsencrypt/live/dili.bkeel.com`（certbot webroot `/var/www/html`，由 certbot.timer 自动续期）。
> - 下面第 9 节「切流改 DNS」对当前拓扑不适用。

## 1. 架构

```text
微信小程序 ──HTTPS──> Nginx(443, dili.bkeel.com) ──> Node(127.0.0.1:13104, systemd: dili)
                                                    ├─ 语音：腾讯云 SentenceRecognition（asr.tencentcloudapi.com）
                                                    ├─ 问答：ASSISTANT_*（当前 TokenHub deepseek/deepseek-flash）
                                                    ├─ 视觉/故事：OPENAI_*（当前 TokenHub deepseek/deepseek-flash）
                                                    └─ 地图：腾讯位置服务（不变）
```

| 目录 | 用途 | 属主/权限 |
|---|---|---|
| `/opt/dili/releases/<sha>` | 代码版本 | root，只读 |
| `/opt/dili/current` | 当前版本软链 | root |
| `/var/lib/dili/data` | `store.json` 运行数据 | dili 750 |
| `/var/lib/dili/assets` | 图片（映射到 `/assets`） | dili 750 |
| `/var/lib/dili/backups` | 数据备份 | dili 750 |
| `/etc/dili/dili.env` | 配置与密钥 | root:dili 640 |

端口：对外只开 80/443。`13104` 仅监听 127.0.0.1；旧的 `3102`（本地 Qwen ASR）新服务器不需要。

## 2. 前置条件（缺一则对应步骤阻塞）

- 新服务器 SSH（有 sudo），Node ≥ 18（推荐 20/22 LTS，路径 `/usr/bin/node`），Nginx，curl。
- 腾讯云账号已开通「语音识别」，为子账号/CAM 用户授予 `QcloudASRFullAccess`（或最小 `asr:SentenceRecognition`），生成 SecretId/SecretKey。
- 国内地域服务器：`dili.bkeel.com` 须完成备案接入，否则 80/443 会被拦截。
- HTTPS 证书（已有证书或允许在服务器上用 ACME 申请）。
- 旧服务器访问方式（用于备份 `store.json` 和图片、读取旧 `.env` 中的模型配置）。

## 3. 本机：打包发布件

```bash
git switch cloud/tencent-migration
npm ci && npm test                        # 必须全部通过
SHA=$(git rev-parse --short HEAD)
git archive --format=tar.gz -o /tmp/dili-$SHA.tar.gz HEAD
scp /tmp/dili-$SHA.tar.gz <new-server>:/tmp/
```

发布件来自 Git，不含 `.env`、`store.json`、`node_modules`。

## 4. 旧服务器：备份数据（只读）

```bash
# 在旧服务器执行（路径以旧 systemd 单元为准，原为 /home/chennuo/project/dili）
bash backup-data.sh /home/chennuo/project/dili/backend/data \
                    /home/chennuo/project/dili/backend/public/assets ~/dili-backup
scp ~/dili-backup/dili-data-*.tar.gz* <new-server>:/tmp/
```

脚本会校验 `store.json` 是合法 JSON，并生成逐文件 SHA256 清单和归档 sha256。

## 5. 新服务器：配置

```bash
# 旧生产 .env 复制到新服务器临时位置后按白名单合并（不打印值）
sudo node scripts/merge-env.js --out /etc/dili/dili.env /tmp/old-prod.env /tmp/migration.env
sudo shred -u /tmp/old-prod.env /tmp/migration.env
```

`migration.env` 只需包含：`TENCENTCLOUD_SECRET_ID`、`TENCENTCLOUD_SECRET_KEY`、`ADMIN_TOKEN`（`openssl rand -hex 24`）。`HOST/PORT/DATA_DIR/ASSET_DIR` 由脚本固定为新服务器值。

## 6. 新服务器：部署

```bash
mkdir -p /tmp/dili-src && tar -xzf /tmp/dili-$SHA.tar.gz -C /tmp/dili-src
sudo bash /tmp/dili-src/deploy/tencent/deploy.sh /tmp/dili-$SHA.tar.gz $SHA
sudo bash /tmp/dili-src/deploy/tencent/restore-data.sh /tmp/dili-data-XXXX.tar.gz        # 先 dry run
sudo bash /tmp/dili-src/deploy/tencent/restore-data.sh /tmp/dili-data-XXXX.tar.gz --yes  # 确认后写入
sudo -u dili env ENV_FILE=/etc/dili/dili.env node /opt/dili/current/scripts/check-env.js --strict
curl -s -H "X-Admin-Token: $ADMIN_TOKEN" http://127.0.0.1:13104/api/admin/check
```

## 7. Nginx 与证书

```bash
sudo cp /opt/dili/current/deploy/tencent/nginx-dili.conf /etc/nginx/conf.d/dili.conf
# 按实际证书位置修改 ssl_certificate 路径；Nginx < 1.25 把 "http2 on;" 改为 "listen 443 ssl http2;"
sudo nginx -t && sudo systemctl reload nginx
```

超时预算（从外到内递减）：小程序 `uploadFile` 75s ＞ Nginx `proxy_read_timeout` 70s ＞ ASR 单次 15s × 最多 2 次 + 退避 ≈ 31s。Node `requestTimeout` 90s 仅兜底。

## 8. 切流前验证（不改 DNS）

```bash
# 在本机把域名临时指向新 IP，只测不计费接口
node scripts/smoke-test.js https://dili.bkeel.com --resolve-ip <NEW_IP>
# 获得计费授权后（每类 ≤3 次，失败也计入）：
node scripts/smoke-test.js https://dili.bkeel.com --resolve-ip <NEW_IP> --paid --audio sample.wav --image sample.jpg
```

## 9. 切流（需 watson 确认后执行）

1. 旧服务停写窗口：短暂停止旧服务 → 再次备份 → 恢复到新服务器（`restore-data.sh --yes`）。
2. Cloudflare 把 `dili.bkeel.com` 的 A 记录改为新 IP（建议先把 TTL 调低）。
3. 真机验收：首页、地点详情图片、语音问答（三个录音入口）、拍照识别、历史记录。
4. 旧服务器保留至少 7 天，不删除数据。

## 10. 注意事项

- 2026-09-30 起文本与视觉统一改用 TokenHub `deepseek/deepseek-flash`（OPENAI_* 与 ASSISTANT_* 配置同一地址/Key），不再依赖 `api.bkeel.com`。
- 微信公众平台合法域名保持 `dili.bkeel.com`，不用改；域名不变时小程序无需重新发布。
- `X-User-Id` 是客户端自报 ID，不是认证，只用于区分历史记录。
- 单进程部署，限流/并发计数在内存中；不要用 PM2 cluster 或多实例。
