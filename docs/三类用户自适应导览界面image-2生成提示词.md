# 三类用户自适应导览界面 image-2 生成提示词

## 使用说明

本文档用于通过 image-2 生成小程序比赛展示图。
建议分多张图生成，不要把所有内容放在一张图里。
整体主题是：**面向普通用户、低视力用户、行动不便用户的自适应历史旅行导览小程序**。

统一视觉方向：

- 微信小程序界面设计
- 城市历史旅行导览主题
- 有北京历史文化感
- 主色使用绿色、白色、浅米色
- 视觉要温暖、清晰、现代、可信
- 体现社会关怀、无障碍、包容性设计
- 不要做成普通旅游 App，要突出“让界面适应不同人群”

统一产品口号：

```text
让每个人都能轻松看见、听见、走近城市历史
```

## 图 1：首次进入用户类型选择页

生成一张微信小程序首次进入页面设计图。
页面用于让用户选择适合自己的使用方式。

页面标题：

```text
请选择适合你的使用方式
```

页面副标题：

```text
我们会根据你的需要调整字号、对比度、语音和路线推荐
```

页面有三个选项：

1. 普通用户
2. 视力障碍 / 低视力用户
3. 行动不便用户

重点布局要求：

- “视力障碍 / 低视力用户”选项必须最醒目
- 这个选项占屏幕上半部分，约占整个屏幕高度的 50%
- 视力障碍选项使用超大字号、高对比度、黑白或深色高对比背景
- 整个视力障碍选项区域都可以点击
- 视力障碍选项内要有清晰示例卡片，让用户站着看手机也能看清

视力障碍选项文案：

```text
视力障碍 / 低视力用户

大字显示
高对比度
语音朗读
更清楚的按钮

选择这个模式
```

视力障碍区域中的示例卡片：

```text
示例
故宫博物院

[播放讲解]
[导航到这里]
```

普通用户选项文案：

```text
普通用户

标准字号
地图发现
历史讲解
路线推荐
```

行动不便用户选项文案：

```text
行动不便用户

少步行路线
少台阶提示
休息点提醒
适合老人和轮椅用户
```

画面重点：

- 让评委一眼看出小程序会根据不同人群提供不同体验
- 不要使用复杂装饰
- 选项卡片要大、清楚、容易点击
- 视力障碍选项必须视觉权重最高

## 图 3：低视力用户模式主界面

生成一张微信小程序主界面设计图。
这是“视力障碍 / 低视力用户”选择后的首页。

页面标题：

```text
大字语音导览
```

页面顶部提示：

```text
已开启：大字模式 · 高对比度 · 语音优先
```

首页优先显示三个超大按钮：

```text
[听附近历史]
[找最近景点]
[问 AI 助手]
```

设计要求：

- 默认大字模式
- 默认高对比度
- 黑色或深色文字，浅色背景
- 按钮高度很大
- 每个按钮文字非常清楚
- 地图弱化，不要让地图占据主要空间
- 列表和语音操作优先
- 不依赖小图标
- 不依赖颜色作为唯一提示

景点卡片内容：

```text
故宫博物院

距离 650 米

明清两代皇宫，适合了解北京中轴线。

[听介绍]  [导航到这里]
```

视觉要求：

- 大字号
- 高行距
- 大按钮
- 卡片数量不要太多
- 每张卡片只显示最核心信息

重点表现：

- 用户不用精细阅读也能完成核心操作
- 看不清小字的人也能快速找到“听讲解”和“导航”
- 这是为低视力用户特别优化的首页

## 图 4：行动不便用户模式主界面

生成一张微信小程序主界面设计图。
这是“行动不便用户”选择后的首页。

页面标题：

```text
轻松出行导览
```

页面顶部提示：

```text
已开启：少步行路线 · 少台阶提示 · 休息点提醒
```

首页优先显示三个大入口：

```text
[找少步行路线]
[查看无障碍景点]
[问 AI 规划轻松行程]
```

页面内容：

- 当前定位
- 附近无障碍友好景点
- 少步行路线推荐
- 休息点提示
- 交通提示
- AI 助手圆形浮窗
- 底部导航栏：首页、地图、路线、收藏、我的

景点卡片内容：

```text
故宫博物院
距离 650 米

路线强度：中等
提示：面积较大，建议选择短路线
适合：老人、陪同出行

[查看无障碍信息] [导航到这里]
```

标签示例：

- 少步行
- 有休息点
- 适合老人
- 轮椅部分友好
- 近停车点

视觉要求：

- 信息要清楚可靠
- 不夸大无障碍能力
- 路线强度和风险提示要明显
- 推荐“适合到达和游览”的景点，而不是只推荐热门景点

重点表现：

- 帮助行动不便用户判断“能不能去、累不累、安全不安全”
- 首页不再只是景点发现，而是轻松出行规划

## 图 6：低视力用户景点详情页

生成一张微信小程序景点详情页设计图。
用户模式：视力障碍 / 低视力用户。
景点：故宫博物院。

页面标题：

```text
故宫博物院
```

页面顶部状态：

```text
大字模式 · 高对比度 · 语音优先
```

页面结构：

- 景点名称超大字号
- 地址和距离
- 超大按钮：播放讲解
- 超大按钮：暂停
- 超大按钮：继续
- 超大按钮：停止
- 倍速选择：0.75x、1x、1.25x
- 要点摘要
- 简明版历史介绍
- 大字时间线
- AI 助手浮窗

要点摘要内容：

```text
这个地方是什么：
明清两代皇宫。

和哪段历史有关：
明清宫廷和北京中轴线。

到现场应该看什么：
午门、太和殿、神武门。
```

历史介绍要求：

- 每段不超过 2 行
- 句子尽量短
- 不要大段文字
- 字号很大
- 行距很高
- 高对比度
- 按钮足够大

视觉要求：

- 整体像“可听、可读、可点”的低视力友好界面
- 不使用浅灰小字
- 不使用密集标签
- 不用复杂地图

重点表现：

- 用户可以直接听讲解
- 用户即使看不清小字，也能看清核心按钮和摘要
- 默认阅读模式是简明版

## 图 7：行动不便用户景点详情页

生成一张微信小程序景点详情页设计图。
用户模式：行动不便用户。
景点：故宫博物院。

页面标题：

```text
故宫博物院
```

页面顶部状态：

```text
轻松出行模式
```

页面结构：

- 景点名称
- 地址和距离
- 无障碍信息模块
- 推荐游览方式
- 风险提示
- 简明历史介绍
- 语音讲解
- 导航到这里
- AI 助手浮窗
- 底部导航栏

无障碍信息模块必须放在历史介绍之前。

无障碍信息示例：

```text
无障碍信息

路线强度：中等
步行距离：约 650 米
台阶情况：部分区域有台阶
轮椅友好：部分区域适合
休息点：有
无障碍卫生间：建议出发前确认
推荐入口：主入口
建议游览方式：选择短路线，预留休息时间
```

风险提示示例：

```text
出行提示：
该景点面积较大，建议由家人或陪同者同行。
如遇排队或道路不平，可优先选择附近短路线。
```

视觉要求：

- 出行信息比历史信息更靠前
- 风险提示清晰但不制造焦虑
- 按钮大而明确
- 展示“查看短路线”“导航到这里”“问 AI 规划轻松行程”

重点表现：

- 帮助行动不便用户出发前判断是否适合前往
- 不是只介绍历史，而是帮助用户安全、省力地游览

## 图 8：三类用户模式对比流程图

生成一张适合比赛路演展示的产品流程图。
主题是“三类人群自适应导览模式”。

画面风格：

- 比赛展示图
- 清晰、现代、有公益感
- 使用流程箭头和图标
- 背景有淡淡的北京历史建筑剪影
- 主色绿色、白色、浅米色

流程结构：

```text
首次进入小程序
        ↓
选择使用方式
        ↓
普通用户 / 低视力用户 / 行动不便用户
        ↓
界面自动适配
        ↓
历史内容、语音讲解、路线推荐、AI 助手
        ↓
让每个人都能轻松看见、听见、走近城市历史
```

三类模式说明：

普通用户：
- 地图发现
- 历史讲解
- 推荐路线

低视力用户：
- 大字模式
- 高对比度
- 语音优先
- 简明摘要

行动不便用户：
- 少步行路线
- 少台阶提示
- 休息点提醒
- 无障碍信息优先

底部口号：

```text
不是让所有人使用同一套界面，
而是让界面主动适应不同人的身体条件和使用困难。
```

重点表现：

- 这是一个有社会关怀的小程序
- 面向老年人、低视力用户、行动不便用户和陪同者
- 体现普惠文化服务和无障碍出行价值
